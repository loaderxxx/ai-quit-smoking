# МЕТОД AI QUIT SMOKING — ПУБЛИЧНАЯ СПЕЦИФИКАЦИЯ

Версия: 0.1  
Статус: HYPOTHESIS-DRIVEN / PUBLIC EXPERIMENT  
Дата: 2026-09-23

## 1. Определение

AI Quit Smoking — это публичная программа, которая соединяет доказательные методы отказа от курения с постоянной разговорной поддержкой AI.

Метод не заявляется как самостоятельное клинически доказанное лечение.

## 2. Формула

**BASELINE → PLAN → CRAVING → ACTION → RESULT → LEARNING → ADAPTATION**

## 3. Базовые правила

1. Цель полного цикла — устойчивый отказ от курения.
2. Доказательные медицинские методы не заменяются AI.
3. В момент тяги приоритет имеет конкретное следующее действие.
4. Каждая значимая тяга может стать единицей обучения.
5. Срыв анализируется как событие, а не как моральная оценка.
6. Метод обновляется только при наличии данных или новых доказательств.
7. Публичная версия должна быть воспроизводимой.

## 4. Craving Protocol

STOP → NAME TRIGGER → CHANGE CONTEXT → APPLY COPING ACTION → AI SUPPORT → REASSESS → RECORD

## 5. Evidence Gate

Каждый новый метод проходит:

CLAIM → SOURCE → CERTAINTY → BENEFIT → RISK → FIT → EXPERIMENT

Популярность метода сама по себе не является основанием для его включения.

## 6. Personalization

Система строит персональную карту:

TRIGGER → TIME → PLACE → SOCIAL CONTEXT → RESPONSE → OUTCOME

Следующие интервенции могут использовать эту карту.

## 7. Clinical Gate

Любой вопрос о лекарстве, дозировке, противопоказаниях, диагнозе или тревожном симптоме проходит медицинский safety gate.

AI может помочь подготовить информацию, но не превращается в автоматического назначающего врача.

## 8. Measurement

Минимум:
- cigarettes/day;
- smoke-free days;
- craving count;
- craving intensity;
- trigger;
- intervention;
- outcome;
- lapse/relapse.

## 9. Adaptation

После каждого значимого цикла:

RESULT → WHAT WORKED → WHAT FAILED → CHANGE → NEXT TEST

## 10. Public Research Loop

REQUEST → CONTEXT → RESEARCH → PUBLIC LOG → SYNTHESIS → METHOD UPDATE → EXPERIMENT → RESULT → PUBLICATION

## 11. Версионирование

v0.1 — исследовательский метод  
v0.2 — после первых реальных данных  
v0.3 — после нескольких итераций  
v1.0 — после валидации базового протокола

## 12. Ключевая гипотеза

> Если доказательные методы сделать доступными в виде постоянной персонализированной AI-поддержки именно в момент реальной тяги, это может сделать процесс отказа более управляемым и повысить приверженность выбранной стратегии.

Это HYPOTHESIS.

Её нужно проверять на реальных задачах и измеримых результатах.

## 13. Definition of Done

Метод нельзя объявлять рабочим только потому, что он красиво написан.

Для повышения версии нужны:
- реальные пользователи;
- фиксированные метрики;
- результаты;
- анализ ошибок;
- повторяемость;
- проверка безопасности;
- соответствующая доказательная база.
