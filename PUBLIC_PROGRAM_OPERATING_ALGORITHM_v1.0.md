# ОСНОВНОЙ АЛГОРИТМ ВЕДЕНИЯ ПУБЛИЧНОЙ ПРОГРАММЫ

Версия: 1.0  
Статус: КАНОНИЧЕСКИЙ АЛГОРИТМ  
Назначение: ведение открытых исследовательских и продуктовых программ в режиме live  
Дата фиксации: 2026-09-23

> Этот документ задаёт основной публичный алгоритм работы проекта. Он переносит в программу AI Quit Smoking организационный принцип Cosmic Programm: рабочий процесс превращается в публичный, версионируемый и проверяемый поток знания.

## 1. Главный принцип

Публичная программа — это не готовый сайт и не архив финальных документов.

Это живая система, в которой читатель может видеть:

ЗАДАЧА → КОНТЕКСТ → ИССЛЕДОВАНИЕ → ПУБЛИЧНЫЙ ЖУРНАЛ → АНАЛИЗ → СИНТЕЗ → МЕТОД → ЭКСПЕРИМЕНТ → РЕЗУЛЬТАТ → ОБНОВЛЕНИЕ → СЛЕДУЮЩИЙ ШАГ

Рабочая информация не должна исчезать в диалоге.

Каждый существенный результат должен становиться одним из двух артефактов:
- публичная запись хода программы;
- устойчивый документ знания, метода или эксперимента.

## 2. Три слоя публичной программы

### LIVE
Что происходит сейчас:
- задача;
- текущий вопрос;
- наблюдение;
- решение;
- результат шага;
- следующий шаг.

### KNOWLEDGE
Что уже стало устойчивым знанием:
- исследования;
- источники;
- систематизированные выводы;
- модели;
- протоколы;
- ограничения;
- открытые вопросы.

### EXPERIMENT
Что ещё не доказано:
- гипотеза;
- дизайн проверки;
- метрики;
- фактический результат;
- стоимость/шум;
- решение KEEP / MODIFY / DISABLE.

## 3. Рабочий цикл

### REQUEST
Фиксируется исходная задача максимально близко к формулировке пользователя.

### CONTEXT
Добавляется необходимый контекст: почему это делается, для кого, что уже известно, что уже было сделано и какие ограничения существуют.

### ROUTE
Определяется, куда должен попасть результат: LIVE LOG, RESEARCH, METHOD, EXPERIMENT, OUTREACH, CONTENT или EVIDENCE.

### ANALYZE
Разделяются:

FACT — подтверждено источником или непосредственно наблюдением.

ASSUMPTION — рабочее предположение.

HYPOTHESIS — проверяемое предположение.

INTERPRETATION — объяснение наблюдения.

FORECAST — ожидание будущего результата.

DESIRE — желаемый результат.

### PLAN
Формируется следующий минимальный набор действий, необходимый для продвижения программы.

### EXECUTE
Исследование, эксперимент, написание, публикация или другой конкретный шаг выполняется.

### VERIFY
Проверяется источник, дата, точность формулировки, соответствие результата задаче, отсутствие внутренних секретов и приватных данных, корректность ссылок и фактическое наличие файла в GitHub.

### REPORT
Результат фиксируется через:

RESULT → WHAT CHANGED → EVIDENCE → NEXT ACTION → OPEN QUESTIONS

### CAPTURE
Устойчивые результаты переводятся в публичное знание.

### NEXT
Определяется следующий исследовательский или продуктовый шаг.

## 4. Правило мгновенной публикации

В режиме публичной программы значимые события публикуются в том же рабочем цикле, а не откладываются на потом.

Если в диалоге произошло новое наблюдение, вывод, изменение гипотезы, найден источник, получен результат, произошёл срыв, найден новый метод, изменился протокол, появился эксперимент или получен пользовательский feedback — создаётся или обновляется соответствующий публичный артефакт.

## 5. Что публикуется автоматически

По умолчанию в публичный контур попадают:
- обезличенный ход исследования;
- публичные выводы;
- источники;
- версия метода;
- результаты экспериментов;
- измерения, которые пользователь разрешил делать публичными;
- ошибки и исправления;
- открытые вопросы;
- следующие шаги;
- публичный контент программы.

## 6. Что НЕ публикуется автоматически

Даже в публичном режиме сохраняется граница PUBLIC / PRIVATE CORE.

Не публиковать автоматически:
- пароли;
- API keys;
- токены;
- приватные контакты;
- внутренние системные промпты;
- защищённую orchestration;
- proprietary algorithms;
- непубличные коммерческие условия;
- юридически чувствительные материалы;
- идентифицирующие персональные данные;
- личные медицинские данные, если пользователь не выразил явное намерение сделать их публичными.

Публичность программы не означает публичность всей личной жизни.

## 7. Исследовательский конвейер

Для каждого глубокого вопроса:

QUESTION → SOURCE DISCOVERY → SOURCE REVIEW → EVIDENCE TABLE → SYNTHESIS → CONFLICT CHECK → HYPOTHESIS → PROTOCOL → EXPERIMENT → RESULT → VERSION

Нельзя сразу превращать один источник в правило программы.

Минимум для важного вывода:
- источник;
- дата;
- тип доказательства;
- что именно источник показывает;
- ограничения;
- что из этого следует для программы;
- что пока НЕ следует.

## 8. Версионирование метода

Метод строится как живой документ:

v0.1 — идея и каркас  
v0.2 — после первичного исследования  
v0.3 — после первых наблюдений  
v1.0 — после подтверждения рабочего базового протокола  
v1.x — улучшения  
v2.0 — изменение фундаментальной модели

Старая версия не удаляется без причины. История изменений сохраняется.

## 9. Публичный журнал

Основной журнал должен отвечать на четыре вопроса:
1. Что произошло?
2. Что мы узнали?
3. На чём основан вывод?
4. Что делаем дальше?

Не превращать журнал в стенограмму каждого слова. Публикуется значимое состояние программы, а не весь шум диалога.

## 10. Пользовательская телеметрия

Для программы отказа от курения потенциально полезны:
- сигареты/день;
- количество smoke-free дней;
- количество и интенсивность тяг;
- триггеры;
- использованный способ совладания;
- результат;
- срыв/возврат;
- самочувствие;
- субъективная уверенность.

Но персональные показатели публикуются только в согласованной форме:

PUBLIC → обезличенные / агрегированные данные  
PRIVATE → индивидуальные медицинские детали

## 11. AI-слой

AI используется как оператор публичного исследовательского конвейера:

OBSERVE → EXTRACT → CLASSIFY → RESEARCH → SYNTHESIZE → PUBLISH → VERIFY → UPDATE

AI не должен выдавать гипотезу за факт.

Для медицинской темы AI должен показывать источник, указывать уровень неопределённости, различать общую информацию и индивидуальную медицинскую рекомендацию и направлять к профессиональной помощи при необходимости.

## 12. Ошибки — часть программы

Ошибка не скрывается.

Правильный формат:

ERROR → WHY → CORRECTION → IMPACT → NEW VERSION

Это позволяет читателю видеть реальное развитие метода.

## 13. Внешнее участие

Публичная программа допускает друзей, читателей, исследователей и будущих пользователей.

Любое внешнее участие может проходить путь:

INVITE → PARTICIPATE → RECORD → ANALYZE → FEEDBACK → UPDATE

Участники не должны раскрывать медицинские или иные чувствительные данные для участия.

## 14. Контур контента

Контент не отделён от исследования.

Путь:

RESEARCH → INSIGHT → STORY → INVITATION → PARTICIPANTS → REAL DATA → RESEARCH UPDATE

Реклама программы должна привлекать людей к реальному эксперименту, а не обещать гарантированный медицинский результат.

## 15. Definition of Done

Публичный исследовательский шаг считается завершённым только когда:
- результат сформулирован;
- факты отделены от интерпретаций;
- ключевые источники добавлены;
- ограничения зафиксированы;
- соответствующий файл обновлён;
- GitHub-запись проверена;
- следующий шаг определён.

## 16. Каноническая формула

РАБОТА НЕ ИСЧЕЗАЕТ.

Каждый существенный шаг должен превращаться в:

СОБЫТИЕ → ДОКАЗАТЕЛЬСТВО → ЗНАНИЕ → МЕТОД → ЭКСПЕРИМЕНТ → РЕЗУЛЬТАТ → НОВУЮ ВЕРСИЮ ПРОГРАММЫ

Именно этот алгоритм является базовым стандартом для дальнейшего ведения публичных программ.
